# Statute browser

A Streamlit view over the statute structure the corpus already holds: which
statutes exist, what sections each one has, and when those sections were
changed by which amending Act.

```powershell
uv run streamlit run apps/statute-browser/app.py
uv run pytest apps/statute-browser/test_statute_browser.py -q
```

No API key, no network, no spend. Everything is read from files on disk.

## What it shows

Three pages, all driven by the same four generated artifacts.

**Corpus overview** lists all 66 statutes with section counts, how many of
those sections changed, the span of years over which they changed, and the
curriculum topics they map to. The table orders oldest first, newest first, or
alphabetically. Charts break the 872 recorded amendments down by decade and
rank the most-amended statutes. Three buttons export the joined tables as CSV.

`STATUTES-BY-DATE.md` holds the same chronological list as a static file,
grouped by legislative era, for reading outside the app. Regenerate it with
`uv run python apps/statute-browser/build_statutes_by_date.py`.

`PRIMARY-STATUES.md` and `SECONDARY-STATUES.md` split the corpus against the
proposed curriculum: primary is what its Category 1 to 3 statute tables name,
secondary is everything else the corpus holds. `build_statute_tiers.py` writes
both, and `--audit` prints how each of the 56 curriculum rows was matched to a
registry row so the mapping can be checked by hand. Two rows are pinned by hand
in its `OVERRIDES` because the curriculum's citation points at a different
statute.

**Statute browser** takes one statute and lists its sections with their
marginal-note headings, how many times each changed, and which Acts did it.
Select a section to get its version history: one line per version, with the
years it ran and the amending provision that opened it. A second tab draws the
same history as a bar chart, one row per section, so the pattern of change
across a statute is visible at a glance.

**Amending Acts** inverts the view. Pick one of the 131 amending Acts and see
every section of every principal enactment it is recorded as touching.

## What the data can and cannot tell you

These limits come from `scripts/build_section_versions.py`, which produced the
version intervals. The app repeats them on every page because they decide how
far the numbers can be pushed.

A version boundary means something changed at that section, not that the
section was replaced. The `operation` field is `unknown` on 853 of the 872
amendment actions, because the source marker names the amending Act and its
section, not what that section did.

Only the current wording is held. Earlier versions are known to exist and are
dated, but their text is not in the corpus. Recovering it needs the 1956 and
1981 revised editions, or the amending Acts themselves.

Every boundary after the first is keyed to the amending Act's year, not its
commencement date. An Act of 1980 may commence in 1981, so a boundary case
cannot be settled from the year alone.

A statute with no amendment history is marked `unknown`, which is not the same
as `unchanged`. 40 of the 66 statutes have no recorded amendment at all.

22 statutes (SRC091 through SRC112) are index-only. The corpus holds their
section numbers and headings but no registry row and no verified text, so
nothing can be cited from them. Their titles come from
`data/legal-sources/extra-statues-to-topics.md`, a proposed mapping rather than
the registry. The app flags them with a badge and a banner.

There is no chapter or part hierarchy anywhere in the corpus. The section index
is flat, so the browser lists sections without grouping them.

Every row carries `status=unverified`, including the CSV exports.

## Where the data comes from

| Artifact | Gives |
| --- | --- |
| `data/legal-sources/manifests/statute-section-index.json` | 5,770 sections, headings, heading provenance, amendment markers |
| `data/processed/actions.csv` | 872 actions: one amending instrument against one target section |
| `data/processed/section_versions.jsonl` | 6,635 dated version intervals built from those actions |
| `data/processed/statute_commencement.csv` | a commencement date for the first version |
| `data/legal-sources/manifests/source-registry.csv` | official title, Act number, year, topics |

`loader.py` joins them and returns four pandas frames. It never writes. The
artifacts stay the source of truth and are regenerated by `scripts/build_*.py`.

## Files

```text
app.py                      st.navigation entry point
loader.py                   joins the artifacts into four frames
shared.py                   cached loaders and the caveat block the pages share
app_pages/overview.py       corpus overview
app_pages/statute.py        per-statute sections and timeline
app_pages/amending_acts.py  per-amending-Act view
build_statutes_by_date.py   writes STATUTES-BY-DATE.md
build_statute_tiers.py      writes the two tier files below
STATUTES-BY-DATE.md         all 66 statutes, oldest first, grouped by era
PRIMARY-STATUES.md          the 52 statutes the curriculum names
SECONDARY-STATUES.md        the 27 in the corpus the curriculum does not name
test_statute_browser.py     offline checks on the joins and the version intervals
```

## Known problems in the upstream data

Two defects turned up while building this and are worked around here rather
than fixed at source.

`section_versions.jsonl` leaves `valid_from_year` null on 1,713 first versions
that do carry a `valid_from_date`. `loader.py` backfills the year from the
date. A further 339 first versions, across 7 index-only statutes, have neither,
so their bars are left out of the timeline chart and the caption says how many.

`source-registry.csv` writes `0` in the `year` column for 16 rows where it
holds no year, including the Evidence Ordinance. Read literally that dates the
Ordinance to the year 0, so `loader.py` treats `0` as missing and falls back to
the commencement year (1896 in that case).

`scripts/build_section_versions.py` reads the section index from
`data/legal-sources/derived/statute-section-index.json`, a path that does not
exist. The live file is under `manifests/`. The script cannot currently be
re-run against the index it claims to read.
